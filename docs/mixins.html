Mixins and Functions

Referencing tokens — token()

token($value, $fallback: null) is the canonical way to reference a Jellyfish CSS custom property from your SCSS. It applies the $token-prefix namespace for you — token(font-primary) expands to var(--jf-font-primary) — so always pass the un-prefixed name. Pass a second argument for a var() fallback: token(table-text-color, inherit). You'll need to interpolate the function if using inside another CSS prop. (This was called v() before v5.)

    
      // Input:
      .element {
        --jf-font-family: #{token(font-primary)};
        font-family: token(font-primary);
      }

      // Output:
      .element {
        --jf-font-family: var(--jf-font-primary);
        font-family: var(--jf-font-primary);
      }

token-or() function

token-or($stem, $fallback-stem) references a component-scoped token that falls back to a shared one — token-or(card-border-color, border-color) expands to var(--jf-card-border-color, var(--jf-border-color)). Use it where the component token is a pure opt-in override seam that isn't declared on :root (the shared token carries the default), so nothing is emitted until a consumer sets it. Card, table and accordion borders use this against --jf-border-color.

get-color() function

The get-color($base, $shade: 500) function references a color from the $colors SCSS map, returning a var() reference so it follows any runtime palette override.

    
      // Input:
      .element {
        color: get-color(primary, 200);
        background-color: get-color(neutral, 1000);
        border-color: get-color(secondary);
      }

      // Output:
      .element {
        color: var(--jf-color-primary-200);
        background-color: var(--jf-color-neutral-1000);
        border-color: var(--jf-color-secondary-500);
      }

If you need the actual colour value instead — for an SVG data-URI (where var() won't resolve), an rgba() with alpha, or a Sass colour function like darken() — use get-color-raw($base, $shade), which returns the literal (e.g. #ff9eba).

get-color-role() function

The get-color-role($base, $role) function references a $colors family by semantic role rather than shade number, returning the role alias custom property. :root resolves that alias to whichever numbered shade $color-{role}-shade points at (set in settings), so retuning a role there moves every call site at once. Valid roles: subtle, muted, emphasis, strong. Bare get-color($base) returns the 500 value.

    
      // Input:
      .element {
        border-color: get-color-role(neutral, muted);
        color: get-color-role(primary, strong);
      }

      // Output:
      .element {
        border-color: var(--jf-color-neutral-muted);
        color: var(--jf-color-primary-strong);
      }

get-on-color() function

The get-on-color($base, $shade: 500) function references the “on colour” for a $colors palette shade — the best-contrast text colour to place on top of it, returning its custom property. Every shade's on-colour is resolved once, in the :root token definitions, rather than recalculated by each component — this is what buttons, chips and tables use to set their text colour.

    
      // Input:
      .element {
        color: get-on-color(primary, 700);
      }

      // Output:
      .element {
        color: var(--jf-color-on-primary-700);
      }

resolve-contrast-color() function

The resolve-contrast-color($color, $color-dark: $color-text) function takes the background color of an element and returns the best color for text on top of it, based on the APCA contrast algorithm — a choice between $color-white and $color-dark (the softer $color-text by default), falling back to $color-black only if neither reaches the contrast threshold. This is the lower-level function used to build the --jf-color-on-{name}-{shade} custom properties once per palette shade; reach for get-on-color() instead when styling a component against a $colors shade.

Where possible, the function will return a custom CSS property rather than a CSS color value.

Under the hood

A few more helpers do the contrast plumbing for the .bg-* modifiers. You shouldn't need to call these — theme an element by putting a .bg-* class on it, not by setting the colour custom properties yourself. For reference: raw-color($value) turns a get-color() reference back into a real colour for Sass maths; palette-ref-parts($value) works out which palette shade a value points at; surface-contrast-color() and surface-heading-color() pick the text and heading colours for a coloured background, ready to assign straight to a custom property.

Working with Text

headings() function

The headings($from: 1, $to: 6) function allows you to apply styles to h1-h6 tags with ease.

    
      // Input:
      #{headings()} {
        font-size: 2em;
      }
      #{headings(3)} {
        color: tomato;
      }
      #{headings(1,4)} {
        text-decoration: underline;
      }

      // Output:
      h1, h2, h3, h4, h5, h6 {
        font-size: 2em;
      }
      h3, h4, h5, h6 {
        color: tomato;
      }
      h1, h2, h3, h4 {
        text-decoration: underline;
      }

Replacing Text with an image

Sometimes you might want to use text on a page for semantics or SEO, but display an image in place. You can do this with the mixin text-replace or the css class .text-replace. It's important to note that you need to give the element a fixed height and width to match your image in order for this to work correctly.

Working with numbers

get-size() function

The get-size($size) function returns the provided size from the $sizing-system SCSS map.

    
      // Input:
      .element {
        width: get-size(0.25);
        height: get-size(4);
      }

      // Output:
      .element {
        width: 0.25rem;
        height: 4rem;
      }

Jellyfish comes with a few simple functions for manipulating numbers.

    
      // Input:
      .some-element {
        width: em(32px);        // 1. Convert a pixel value to an em value based on a docroot em sixe of 16px
        height: h(100vh);       // 2. Half a given value
        margin-left: n(20px);   // 3. Return the negative of a given value
        margin-right: hn(30px); // 4. Return the negative, half of a given value
        margin-top: nh(50px);   // 4. Return the negative, half of a given value
      }

      // Output:
      .some-element {
        width: 2em;             // 1. Convert a pixel value to an em value based on a docroot em sixe of 16px
        height: 50vh;           // 2. Half a given value
        margin-left: -20px;     // 3. Return the negative of a given value
        margin-right: -15px;    // 4. Return the negative, half of a given value
        margin-top: -25px;      // 4. Return the negative, half of a given value
      }

Working with Pseudo elements ::before and ::after

Pseudo elements always need a few properties defined. The pseudo($content: "", $display: block, $pos: absolute) mixin accepts three arguments and has default fallbacks.

    
      // Input
      .some-element::before {
        @include pseudo;
      }
      .some-other-element::before {
        @include pseudo('> ','inline-block','relative')
      }

      // Output
      .some-element::before {
        content: '';
        display: block;
        position: absolute;
      }
      .some-other-element::before {
        content: '> ';
        display: inline-block;
        position: relative;
      }
