Mixins and Functions

Referencing tokens — token()

token($value, $fallback: null) is the canonical way to reference a Jellyfish CSS custom property from your SCSS. It applies the $token-prefix namespace for you — token(font-primary) expands to var(--jf-font-primary) — so always pass the un-prefixed name. Pass a second argument for a var() fallback: token(table-text-color, inherit). You'll need to interpolate the function if using inside another CSS prop. (This was called v() before v5.)

    
      // Input:
      .element {
        --jf-font-family: #{token(font-primary)};
        font-family: token(font-primary);
      }

      // Output:
      .element {
        --jf-font-family: var(--jf-font-primary);
        font-family: var(--jf-font-primary);
      }

token-or() function

token-or($stem, $fallback-stem) references a component-scoped token that falls back to a shared one — token-or(card-border-color, border-color) expands to var(--jf-card-border-color, var(--jf-border-color)). Use it where the component token is a pure opt-in override seam that isn't declared on :root (the shared token carries the default), so nothing is emitted until a consumer sets it. Card, table and accordion borders use this against --jf-border-color.

Working with Colors

The whole consumer-facing colour API is five functions plus token():

FunctionReach for it when…
get-color($family, $shade)you want a specific numbered shade of a palette family.

get-color() function

The get-color($base, $shade: 500) function references a color from the $colors SCSS map, returning a var() reference so it follows any runtime palette override.

    
      // Input:
      .element {
        color: get-color(primary, 200);
        background-color: get-color(neutral, 1000);
        border-color: get-color(secondary);
      }

      // Output:
      .element {
        color: var(--jf-color-primary-200);
        background-color: var(--jf-color-neutral-1000);
        border-color: var(--jf-color-secondary-500);
      }

If you need the actual colour value instead — for an SVG data-URI (where var() won't resolve), an rgba() with alpha, or a Sass colour function like darken() — use get-color-raw($base, $shade), which returns the literal (e.g. #ff9eba).

get-color-role() function

The get-color-role($base, $role) function references a $colors family by semantic role rather than shade number, returning the role alias custom property. :root resolves that alias to whichever numbered shade the $color-role-shades map points at (set in settings), so retuning a role there moves every call site at once. Valid roles: subtle, muted, emphasis, strong. Bare get-color($base) returns the 500 value. For the raw shade number at build time (Sass maths, token interpolation) use role-shade($role).

    
      // Input:
      .element {
        border-color: get-color-role(neutral, muted);
        color: get-color-role(primary, strong);
      }

      // Output:
      .element {
        border-color: var(--jf-color-neutral-muted);
        color: var(--jf-color-primary-strong);
      }

get-on-color() function

The get-on-color() function returns the text (“on”) colour for a background, in two call styles:

  • get-on-color($family, $shade: 500) — the shade's paired on-colour custom property. Resolved once in the :root token definitions, not recalculated per component; this is what buttons, chips and tables use.
  • get-on-color($value) — text that fits an already-resolved value: a --jf-color-* reference (numbered or role) maps to its -on-* companion so the text flips with its background; a bare --jf-color-bg / -bg-soft / -bg-inverse maps to its paired text token; a one-off colour falls through to resolve-contrast-color(). Use this when a component's background is a token or setting rather than a known ($family, $shade) — e.g. the navbar link text.
    
      // Input:
      .element {
        color: get-on-color(primary, 700);
      }

      // Output:
      .element {
        color: var(--jf-color-on-primary-700);
      }

resolve-contrast-color() function

The resolve-contrast-color($color, $color-dark: $color-text) function takes the background color of an element and returns the best color for text on top of it, based on the APCA contrast algorithm — a choice between $color-white and $color-dark (the softer $color-text by default), falling back to $color-black only if neither reaches the contrast threshold. This is the lower-level function used to build the --jf-color-on-{name}-{shade} custom properties once per palette shade; reach for get-on-color() instead when styling a component against a $colors shade.

Where possible, the function will return a custom CSS property rather than a CSS color value.

Under the hood

A few more helpers do the contrast plumbing for the .bg-* modifiers. You shouldn't need to call these — theme an element by putting a .bg-* class on it, not by setting the colour custom properties yourself. For reference: raw-color($value) turns a get-color() reference back into a real colour for Sass maths; palette-ref-parts($value) works out which palette shade a value points at; surface-contrast-color() and surface-heading-color() pick the text and heading colours for a coloured background, ready to assign straight to a custom property.

Working with Text

headings() function

The headings($from: 1, $to: 6) function allows you to apply styles to h1-h6 tags with ease.

    
      // Input:
      #{headings()} {
        font-size: 2em;
      }
      #{headings(3)} {
        color: tomato;
      }
      #{headings(1,4)} {
        text-decoration: underline;
      }

      // Output:
      h1, h2, h3, h4, h5, h6 {
        font-size: 2em;
      }
      h3, h4, h5, h6 {
        color: tomato;
      }
      h1, h2, h3, h4 {
        text-decoration: underline;
      }

type() mixin — fluid size + paired leading

type($step, $important: false) is the single seam for heading-scale type. It sets font-size to a $type-scale step (a fluid clamp() for md and up) and the line-height that $type-leading pairs with that step — so size and leading can't drift apart.

    
      .lead-in {
        @include type(2xl);   // font-size: var(--jf-font-size-2xl); line-height: var(--jf-leading-tight);
      }

h1()…h6() are thin wrappers — @include h2() is type() with the step from $heading-scale. The .h1–.h6 utility classes call them with $important: true so they win over element styles; the <h1>–<h6> element rules don't. leading-for($step) returns just the leading key for a step.

fluid() / rem() functions

fluid($minPx, $maxPx, $minVw, $maxVw) builds a clamp() that slides between two pixel sizes across a viewport range (defaulting to $fluid-min-vw–$fluid-max-vw) — fluid(24px, 30px) → clamp(1.5rem, …vw + …rem, 1.875rem). rem($value) converts a pixel value to rem (relative to $root-size); non-pixel values pass through untouched. It also backs the container-query mixins.

Replacing Text with an image

Sometimes you might want to use text on a page for semantics or SEO, but display an image in place. You can do this with the mixin text-replace or the css class .text-replace. It's important to note that you need to give the element a fixed height and width to match your image in order for this to work correctly.

Working with numbers

get-space() and get-size() are companions with distinct jobs. Reach for the one that matches what you're setting:

  • get-space($step) — flow between elements: margin, padding, gap, gutters, insets. Vertical and horizontal rhythm and balance.
  • get-size($size) — the fixed size of a thing: width, height, icon and control dimensions, background-size.

get-space() function

Use get-space($step) for spacing between elements. It returns a --jf-space-* token reference (see the spacing scale), so the value stays runtime-themeable — a theme can tighten or loosen the whole framework's rhythm by re-declaring the custom properties.

    
      .element {
        padding: get-space(md);          // var(--jf-space-md)
        margin-block-end: get-space(lg); // var(--jf-space-lg)
        gap: get-space(sm);              // var(--jf-space-sm)
      }

get-size() function

get-size($size) returns a raw length from the $sizing-system map — a build-time value, not a token. Use it for fixed dimensions, and wherever you need an actual number rather than a var(): Sass maths, calc() operands, generator loops.

    
      // Input:
      .element {
        width: get-size(0.25);
        height: get-size(4);
      }

      // Output:
      .element {
        width: 0.25rem;
        height: 4rem;
      }

Non-colour axis accessors

Analogues of get-color-role() for the other design axes — each is a one-line _map-token() call that validates the step against its scale map and returns the --jf-* reference (with a build-time error listing the valid keys if you mistype). See the token tables for the steps.

build-shadow($entry) assembles a box-shadow value from a $shadow-scale entry — each (geometry, alpha) tuple becomes <geometry> color-mix(in srgb, var(--jf-shadow-color) <alpha>, transparent).

em($pixels) converts a pixel value to em, relative to a 16px root — em(32px) gives 2em.

Global motion() transitions

Use @include motion($properties...) to apply the framework transition to one or more properties. Each transitions on var(--jf-transition) (var(--jf-duration-base) var(--jf-ease-in-out)), so prefers-reduced-motion — which zeroes the --jf-duration-* tokens — switches these off automatically.

Single property? Write transition: var(--jf-transition) directly — motion() earns its keep on the multi-property case, where it saves repeating the token per clause.

Different speed or curve? Redefine --jf-transition (or --jf-duration-base / a --jf-ease-* curve) on the element or a scope — it cascades, so a whole region can run slower without touching the mixin.

      .drawer {
        --jf-transition: var(--jf-duration-slow) var(--jf-ease-out);
        @include motion(transform, opacity); // slow + ease-out, and so is everything under .drawer
      }

Working with Pseudo elements ::before and ::after

Pseudo elements always need a few properties defined. The pseudo($content: "", $display: block, $pos: absolute) mixin accepts three arguments and has default fallbacks.

    
      // Input
      .some-element::before {
        @include pseudo;
      }
      .some-other-element::before {
        @include pseudo('> ','inline-block','relative')
      }

      // Output
      .some-element::before {
        content: '';
        display: block;
        position: absolute;
      }
      .some-other-element::before {
        content: '> ';
        display: inline-block;
        position: relative;
      }
