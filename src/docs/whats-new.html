What's New

Dark mode

Jellyfish now ships a dark theme. It's a class on <html> — so a consumer can override any single dark value at runtime and get a clean three-way control: .jf-dark forces dark, .jf-light forces light (even on a dark OS), and with neither the OS prefers-color-scheme decides.

Only the semantic tokens and the step-role aliases are repointed in dark — the numbered primitives (--jf-color-primary-500 …) and their build-time -contrast / -on-* companions are untouched, so .bg-* sections and themed component fills render identically in both modes while surfaces, text, borders and links flip. New settings: $dark-mode-enabled (default true; set false to drop the block), $dark-body-background-color, $dark-color-role-shades.

The bundled theme.js exposes window.JellyfishTheme (get / set / toggle), wires any [data-theme-toggle] / [data-theme-set] control by delegation, follows live OS changes while no explicit choice is stored, and fires jfThemeChange. Add <meta name="color-scheme" content="light dark"> and a small pre-paint snippet to your <head> — see Getting Started, Theme Colors and Javascript.

Role-addressable --jf-color-on-* companions

Alongside the numbered --jf-color-on-{family}-{shade} tokens, every step-role now has a matching --jf-color-on-{family}-{role} (-subtle / -muted / -emphasis / -strong, plus bare for the 500). It tracks the same $color-role-shades entry as the role alias itself, so a role surface and its paired text can't drift apart when a role is retuned — and the dark-mode role remap carries the text with it. Value-neutral in light mode.

Surface (.bg-*) modifiers

A .bg-{family} class is now generated for every colour in $colors (.bg-primary, .bg-neutral, …). Put one on any element — a section, a .card, a div — and it becomes a themed surface: --jf-color-surface and its contrast-picked --jf-color-text / --jf-color-headings are set for you, the muted / subtle text tiers re-tint toward it, and everything nested (headings, .text-muted, callouts, cards) follows by inheritance — no descendant selectors. Add specific shades or one-off colours via the $background-colors map. See Theme Colors.

Neutral surfaces: .bg-soft / .bg-inverse

Two neutral surfaces sit alongside the families and flip with the theme. .bg-soft is a step of elevation off the canvas — literal white in light (a gentle lift against the warm off-white body), a raised dark tint in dark — and is what a panel, callout, chip or modal now reaches for to read as slightly raised without taking a theme colour. .bg-inverse is a full reverse of the page: the opposite theme's canvas, for a deliberate high-contrast block. Both carry their paired text / heading colours and re-mix the muted / subtle tiers, built from flipping tokens (--jf-color-bg-soft / -text-soft / -headings-soft and the -inverse set), tuned per project via $soft-background-color / $dark-soft-background-color.

Breaking: .bg-white is removed — use .bg-soft. The component .white modifiers go the same way: .button.white → .button.soft, .chip.white → .chip.soft (with a new .chip.inverse), .progress.white → .progress.soft, .callout.white → .callout.soft. A plain .modal is now its own .bg-soft-level surface, so modal text no longer comes out dark-on-dark — drop any .bg-white from your <dialog class="modal"> markup.

Components as surfaces

A component that paints its own background now also declares itself a surface — it sets --jf-color-surface / -text / -headings and re-mixes the muted / subtle text tiers against its own fill. So a nested .text-muted, figcaption or .font-size-small inside a .callout (or .modal) tints toward the callout, not the page — no more grey-on-tint clash, in either mode. The --jf-callout-* seams still work, defaulting to the surface. Transparent-by-design components (.card, accordion panels) are deliberately not surfaces — they read whatever they sit on.

Navbar — light / dark out of the box

The navbar colour set runs on the semantic layer. The top bar is branded — $navbar-family (primary) at 500 in both modes — and its link / hover text is derived from the background, like a .bg-* surface, so any bar colour comes with fitting text. Set the bar to a shade or a one-off colour and the text follows; retune it directly with --jf-navbar-link-color if you want.

Dropdown panels, and the whole menu below the breakpoint (the mobile menu / off-canvas drawer) are a neutral .bg-soft surface that flips with the theme — subtle links, a light neutral hover tint. The branded strip stays on .navbar-brand with the logo and hamburger. The four sub-menu values are exposed as --jf-navbar-sublink-* on :root, so one override retunes the dropdown, mobile menu and drawer together. Dropdown arrows and link borders draw with currentColor, so they sit right on whatever surface they're on. Structure and markup are unchanged — this is the token wiring.

New heading mixin

Sometimes you want to add the font sizes of a heading level element (eg. h2) but don't want to - or can't - add a .h2 class (e.g. when modifying vendor markup).

Previously you might have used @extend .h2; to do this, but this is problematic as css could get unwieldly due to any reference to the .h2 class being included in the generated css.

Now you can simply @include h2(); to apply line height and responsive font-size without the need for a specific class.

This will have the same font-size and line-height as a h3 tag

      
        .is-h3-size {
          @include h3(); // Applies h3 font-size and line-height
        }

Design token axes beyond colour

The non-colour design axes are now tokens too, each a thin semantic scale with a matching get-*() accessor (see Variables and Mixins):

  • Spacing — --jf-space-{3xs…2xl} scale + get-space(), plus --jf-flow for block-flow rhythm (bottom margin between block elements) — which $space-scale step it uses is set by $flow-step (default md). The $sizing-system map stays Sass-only. v4's $element-margin / $element-padding are removed.
  • Line height — --jf-leading-{flush,tight,snug,base,loose}. get-leading().
  • Font weight — the nine named weights as --jf-font-weight-*; get-weight(). Repoint semibold/medium etc. at runtime.
  • Radius — --jf-radius-{none,xs,sm,md,lg,xl,2xl,full}. get-radius(). Round or sharpen every corner from the $radius-scale map.
  • Border width — --jf-border-width + --jf-border-width-strong (1px / 2px).
  • Elevation — --jf-shadow-{none,xs…xl}, each mixing --jf-shadow-color toward transparent at the step's alpha. Geometry in $shadow-scale; get-shadow().
  • Motion — --jf-duration-{instant,fast,base,slow,slower}, --jf-ease-{in,out,in-out,spring}, composed --jf-transition. get-duration() / get-ease(). prefers-reduced-motion zeroes the durations in one place, so all framework transitions honour it automatically — the accordion chevron, off-canvas drawer and docs animations were all swept onto the token, $accordion-transition-duration is removed, and the indeterminate progress bar is clamped slow (min 10s) instead of freezing. Smooth in-page scrolling is now scoped to html:focus-within (keyboard / anchor navigation only).

The smooth() mixin is renamed motion() (smooth() still works as an alias). For an off-tempo transition, redefine --jf-transition (or its parts) on a scope — it cascades.

Grid

New .grid — a CSS Grid on the same 12-column class API as .row. Use .grid by default; keep .row (flexbox) where you need grow-to-fill columns. Also new: .auto-grid (count-agnostic equal columns), .col-start / .col-end placement utilities, and .collapse (zero-gutter) now on both engines.

  • Container is bleed-friendly. Its side space is 100%-based padding (exact — content is precisely --jf-container-max). New .bleed / .bleed-start / .bleed-end helpers (with -{bp} and -none-{bp} variants) break an element out to the page edge — put .bleed-end on the last column of a two-column .grid for the classic image-off-the-edge layout. Optional .page + --jf-page-max caps the shell on ultrawide monitors. Knobs: --jf-container-max, --jf-container-gutter, --jf-page-max.
  • Breakpoints are fixed at 600 / 900 / 1200 / 1800. $breakpoints is a flat key: px map, no longer a !default. Per-breakpoint container / gutter / root-size values moved to custom properties.
  • Removed: .offset-* and push/pull; $cols, $grid-has-order, $grid-has-offset, $base-col-name, $base-container-gutter, $base-col-gutter; the per-breakpoint root-font-size / root-line-height retune. Full migration table.

Forms

  • <select> sizes to its widest option. The arbitrary width: 300px; max-width: 60% default is gone — <select> is now width: fit-content with max-width: 100%, so it never overflows its container. It still fills a .col / .form-row; set width yourself for a fixed size.
  • Control font size is max(16px, 1em), not 16px !important — still no iOS focus-zoom, but it scales with context and the !important is gone.
  • <textarea> auto-grows via field-sizing: content where supported; rows sets the starting height.
  • Validation states. :user-invalid (and [aria-invalid="true"] for server-rendered errors) turn a field's border error after interaction — no JS. New .form-hint / .form-error message classes. See Forms.
  • Grouped controls. The docs now model related checkbox / radio sets as <fieldset> + <legend>. New .is-plain strips a fieldset's border to read as a plain label + controls, and .form-group-inline now works on a <fieldset> (legend stays above the inline row).
  • Forced-colors hardening. The progress bar, the accordion chevron and the modal close / prev / next glyphs are repainted with system colours under Windows High Contrast (forced-colors: active) so they stay visible in every state. All of it lives in one block in the accessibility partial.

Fluid type

The type scale is now rem (was em). xs / sm / base stay fixed; md and everything above — all the headings — are single clamp() values that scale smoothly with the viewport (320–1240px), no breakpoints. Each size carries its own line-height: one type($step) mixin sets font-size and the paired leading together, and <h1>–<h6>, the .h1–.h6 classes and @include h2() all route through it. Retune with $type-scale / $heading-scale / $type-leading. $font-sizes-h1…h6 and $heading-line-height are gone.

New optional $measure (default none) caps reading-text line length — set 66ch or so, or flip --jf-measure on per-context.

--jf-root-font-size now sits on <html>, so with the scale in rem a single override scales the whole framework's type — :root { --jf-root-font-size: 1.25rem } for a large-print build. And new $font-size-adjust (default none) normalises apparent size when you swap in a typeface that reads small or large.

Loose ends tidied with it: hard-coded line-height values across the framework (table, buttons, pre, chips, inputs, print…) now go through get-leading(); table and buttons gain $table-line-height / $button-line-height. Breaking: the .small text utility is now .font-size-small — .small is removed (no alias), because it collided with the .button.small / .chip.small size modifiers. It also now carries its own line-height rather than inheriting. New .standfirst utility for a lead paragraph (one step up the scale, medium weight, paired leading).

h1–h3 use text-wrap: balance to even out short multi-line headings; p, li, dd and figcaption use text-wrap: pretty to trim orphans and bad breaks. Browsers without support ignore both.

Modern reset

The Meyer v4 reset is replaced with a small modern one (Andy Bell shape). box-sizing: border-box is set directly on every element rather than inherited from <html> (so a stray html { box-sizing } from another stylesheet can't cascade in); UA margins are stripped with * { margin: 0 } and Jellyfish re-adds its own flow spacing; img / picture / video / canvas are display: block and capped at max-inline-size: 100%; form controls get font: inherit; and text-size-adjust: none stops mobile browsers auto-inflating text.

The old “HTML5 display-role” block that forced section / article / figure etc. to display: block is gone — every supported browser does that natively. Breaking: list-marker removal is now opt-in via role="list" — <ul role="list"> / <ol role="list"> drop the marker and indent (and keep announcing as a list in Safari/VoiceOver). Bare <ul> / <ol> are unchanged (Jellyfish still styles them by element).

Floats contain themselves

With .clearfix gone, common block containers (div, section, article, p, li, figure, blockquote, aside, header, footer, dd, main) now get display: flow-root automatically when they hold a directly-floated .align-* child, via :has(). The rule has zero specificity, so an explicit display on the parent — yours, a plugin's, or a Jellyfish .grid / .row — always wins. For any other element, set display: flow-root yourself.

Hyphenate long email addresses

Long email addresses in <a href="mailto:"> links will now hyphenate automatically to prevent overflow issues in small containers.

@container support

There are new shorthand SASS mixins for container queries:

    
      .parent-container {
        container-type: inline-size;
        container-name: parent-container;
      }
      .col-container {
        container-type: inline-size;
        container-name: column-container;
      }


      // 1. Applies when the nearest container is >= 400px
      .card.container-query-1 {
        @include container-above(400px) {
          flex-direction: row;
        }
      }
      // 2. Applies when the nearest container is < 400px
      .card.container-query-2 {
        @include container-below(400px) {
          border-color: var(--jf-color-primary-500);
          border-width: 4px;
        }
      }
      // 3. Applies when the nearest container is < 420px and >= 400px
      .card.container-query-3 {
        @include container-between(400px, 420px) {
          background: var(--jf-color-secondary-200);
        }
      }
      // 4. Applies when the nearest named container is < 400px and >= 800px
      .card.container-query-4 {
        @include container-between(400px, 800px, "parent-container") {
          box-shadow: 3px 3px 4px rgba(0, 0, 0, 0.6);
        }
      }
      // 5. Applies when a named container is >= 800px
      .card.container-query-5 {
        @include container-above(800px, "parent-container") {
          font-family: $font-monospace;
        }
      }
      // 6. Applies when the nearest container is >= 400px, only below lg breakpoint
      .card.container-query-6 {
        @include below(lg) {
          @include container-above(400px) {
            border-color: var(--jf-color-primary-500);
            border-width: 4px;
          }
        }
      }
