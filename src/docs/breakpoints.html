Breakpoints[ Variable Reference ]

Four fixed breakpoints — sm 600px, md 900px, lg 1200px, xl 1800px.

They live in the $breakpoints SCSS map as a flat key: px lookup. The keys are the class-name namespace for the grid and visibility APIs (.md-6, .order-sm-3, .hide-lg…); the values feed the media-query mixins below.

The map is fixed — not a consumer override surface. Pre-container-query, fine-grained breakpoint tuning had to happen in the Sass map; it doesn't now. That doesn't lock you to four widths: the media-query mixins take a raw px value too, so @include above(950px) works and compiles to a plain @media (min-width: 59.375em) — you're just not registering a named breakpoint (no .950-6 column classes get generated). Container queries and hand-written @media cover the rest.

What the map used to carry per breakpoint — container width / max-width / gutter, column gutter, root font-size / line-height — is now custom properties you override at :root or a scope: --jf-container-max, --jf-container-gutter, --jf-grid-gutter, --jf-root-font-size, --jf-root-line-height. See the grid migration table.

Note: the JavaScript breakPoints object (src/js/breakpoints.js) mirrors these values for scripts that need them. It's already in sync and, now the values are fixed, stays that way.

Media queries

Jellyfish comes with three media query mixins. Pass either a $breakpoint name (sm / md / lg / xl) or an arbitrary px value — both resolve to an em-based @media query. The examples below are all valid.

    
      // 1. Use the mixin within an element declaration
      body {
        @include above(sm) {
            background-color: #ff3c74;
        }
      }
      // 2. Add element declarations within the mixin
      @include between(sm,md) {
        .element {
            background: linear-gradient(to right, #ff3c74 0%, #ffa0cd 100%);
        }
      }
      .element {
        // Pass a pixel value
        @include below(600px) {
          transform: rotate(100deg);
        }
        // Mix pixel values with breakpoint names
        @include between(600px,lg) {
          transition-duration: 10s;
        }
        // Pass a breakpoint name
        @include above(lg) {
          transition-timing-function: cubic-bezier(0.9, 0.1, .2, .4);
        }
      }
Mixin Result
@include above($min) {...} CSS contained within the brackets will apply above the given breakpoint, until overwritten by specificity or a higher breakpoint.
@include between($min, $max) {...} CSS will apply between the two specified breakpoints only.
@include below($max) {...} CSS applies below the given breakpoint, unless overridden by specificity. As a general rule, it's best to use above() rather than below().
