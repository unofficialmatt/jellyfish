Modals[ Variable Reference ]

Since v4.1.0, Jellyfish has included support for native <dialog> elements for the display of modals. This removes dependencies on external Javascript libraries and ensures that modal elements are accessible as standard.

To avoid being opinionated on the <dialog> element, the .modal class is required on the element. Open a modal with a data-modal-target="id" attribute on any button (the argument is the dialog's id); the bundled script handles the click by delegation, so no inline onclick is needed and it works under a Content-Security-Policy. A close button is appended to every modal automatically; you can also put data-modal-close on your own button anywhere inside the modal.

To preserve padding and layout, a .modal should contain a .modal-content element, used to contain the modal's content. The .modal element is a flex element; consequently adding .modal-header or .modal-footer will ensure they are always visible. This allows for key information or call-to-actions to always be in sight.

The dialog is its own surface at the .bg-soft level — white-ish in light, a raised dark tint in dark — so its text, headings and muted tiers are set against the panel, not inherited from the page. You don't need (and shouldn't add) a .bg-* class on the <dialog>; override --jf-color-surface on .modal if you want a different fill.

Opening and closing

data-modal-target="id" on a button opens (or toggles) that modal; data-modal-close on any element inside a modal closes it. Both are handled by delegation in the bundled script. If you drive modals from your own code, toggleModal('id') is still exposed globally.

Dismiss: Escape always closes a modal, and a click on the dark backdrop closes it too. Add closedby="any" to the <dialog> (as in the example above) so browsers that support it handle the click-outside natively; the bundled script does the same for those that don't.

Animation: opening slides the modal up and scales it in, with the backdrop fading, over --jf-transition (via @starting-style). Closing is an opacity-only dissolve at the slightly slower --jf-duration-slow, held in place with transition-behavior: allow-discrete — that leg needs the overlay property, so the fade-out runs in Chromium and Safari but Firefox cuts straight to closed (it opens the same everywhere). prefers-reduced-motion: reduce collapses both to an instant change. Retune per modal by redeclaring --jf-transition / --jf-duration-slow on .modal, or the whole entry by overriding the @starting-style transform. Stepping through a group with the arrows / arrow keys is a hard cut — the animation only runs when a modal opens or closes on its own.

Nested modals: a modal opened from a button inside another modal (outside of modal groups) isn't supported — the script tracks a single open modal, so the first one's state is lost. Close one before opening the next, or use a modal group.

Modal groups

You can combine modals into a group, which will automatically append navigation arrows to the modals within the group. The user can also navigate via keyboard (left and right arrows). Just add a data-modalgroup attribute to the modals within the group.

None of these modals have a heading, so their modalTitle (see Javascript API below) falls back to their first paragraph's text - eg. "This content is in the first modal of the group" for Modal 1. modal-group-4 instead has a data-title attribute, which takes priority over its paragraph text.

Javascript API

When a modal is opened, a jfModalOpened event is fired. This event can be hooked into, for example to autoplay a video that is embedded in the modal. The event.detail property contains the ID of the modal element.

    
      document.addEventListener("jfModalOpened", function (event) {
        console.log(event.detail);
        // Object { newModalId: "modal-group-1" }
      });

Likewise, when a modal is closed, a jfModalClosed event is fired. This event is triggered when the user presses Escape, clicks on the close button, clicks outside of the dialog (on the overlay) or uses the navigation keys to move through a modalGroup.

    
      document.addEventListener("jfModalClosed", function (event) {
        console.log(event.detail);
        // Object { closedModalId: "modal-group-1" }
      });

Note: alongside these events, Jellyfish automatically pushes modalOpened and modalClosed events to window.dataLayer if it exists, for Google Tag Manager. Nothing is sent if dataLayer isn't present on the page. modalTitle is resolved in priority order: a data-title attribute on the modal, then the first heading (h1-h6) found in the modal, then the first non-empty text content found in the modal - an empty string if none of these are present.

    
      // On open (modal has a heading):
      dataLayer.push({
        event: "modalOpened",
        modalId: "#dialog",
        modalTitle: "This is a modal",
      });

      // On open (modal has a data-title attribute - takes priority over its content):
      dataLayer.push({
        event: "modalOpened",
        modalId: "#modal-group-4",
        modalTitle: "Modal Four",
      });

      // On open (modal has no data-title or heading - falls back to its first text content):
      dataLayer.push({
        event: "modalOpened",
        modalId: "#modal-group-1",
        modalTitle: "This content is in the first modal of the group",
      });

      // On close:
      dataLayer.push({
        event: "modalClosed",
        modalId: "#dialog",
        modalTitle: "This is a modal",
        timeOpen: 4, // seconds the modal was open for
      });
